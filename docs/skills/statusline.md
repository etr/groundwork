# `statusline`

> **Run it:** `/groundwork:statusline [install|uninstall]` · **Tier:** user-run · **Reads:** `$HOME/.claude/settings.json`; whether `jq` and `curl` are installed · **Writes:** `$HOME/.claude/groundwork-statusline.sh` (an executable wrapper) and the `statusLine` key of `$HOME/.claude/settings.json`; uninstall removes both

## What it does

Installs or removes Groundwork's optional statusline. Install writes a small wrapper, `$HOME/.claude/groundwork-statusline.sh`, and points the `statusLine` key of `$HOME/.claude/settings.json` at it, leaving every other setting alone. Uninstall removes that key and then the wrapper, and only when Groundwork owns the configured statusline. With no action it installs; any other action is rejected.

## When to reach for it

- You want Groundwork's statusline in Claude Code.
- You want it removed without losing your other settings.
- **Not when:** you did not ask for it. Its first rule is to configure the statusline only after you explicitly invoke the workflow.

## Common questions

**I already have a statusline from another tool. Will it be overwritten?**

Not without your say-so. If a different `statusLine` exists, install asks before replacing it, and stops without touching settings or the wrapper if you decline. Uninstall leaves a foreign statusline and the wrapper untouched, and reports that Groundwork does not own the active statusline.

**Why a new file in `~/.claude/` rather than a path straight to the plugin?**

Claude Code does not expand `${CLAUDE_PLUGIN_ROOT}` inside a user `statusLine` command, and marketplace installs are versioned. The stable wrapper makes future plugin upgrades use the newest installed Groundwork version. Installing again over an existing Groundwork statusline just refreshes the wrapper.

**What has to be installed first?**

`jq` and `curl`. Before modifying any file it runs `command -v jq` and `command -v curl`; if either is missing, it stops and reports which dependency must be installed. `gh` is optional and only adds pull-request information.

**I use the Codex export. Is it the same?**

No. There the installer swaps in a separate body, `codex-skill-body.md`, which sets `[tui] status_line` in `${CODEX_HOME:-$HOME/.codex}/config.toml`. Codex cannot display the selected Groundwork monorepo project.

## It's working if

- Before any file changed, `command -v jq` and `command -v curl` were run.
- `$HOME/.claude/groundwork-statusline.sh` exists, is executable, and carries the line `# Auto-generated by /groundwork:statusline.`
- In `$HOME/.claude/settings.json` only `statusLine` changed: `"type": "command"`, `"command": "bash <HOME_DIR>/.claude/groundwork-statusline.sh"`, `"height": 3` — with an absolute home path, not `~`.
- Every unrelated setting in `settings.json` is still there.
- It reported installation complete and said Claude Code must be restarted to display it.
- On uninstall, only the `statusLine` key was removed, then the wrapper — and only because the command invoked `$HOME/.claude/groundwork-statusline.sh`.

**It is not working if:** a setting other than `statusLine` disappeared from `settings.json`, the command contains `~`, or a statusline that was not Groundwork's was replaced or removed without asking.
